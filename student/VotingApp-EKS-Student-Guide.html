2. Final CI/CD architecture

Pipeline: GitHub → Jenkins EC2 → SonarQube EC2 → Docker Buildx → ECR → EKS.

3. Application data flow

Browser → Vote (Python) → Redis → Worker (.NET) → PostgreSQL → Result (Node.js). Redis and PostgreSQL are internal ClusterIP Services. Vote and Result are also ClusterIP in this lab.

4. Prerequisites

  • Existing EKS cluster active and worker nodes Ready.
  • Jenkins EC2 has Java, Jenkins, Git, Docker Engine/Buildx, AWS CLI v2, kubectl and SonarScanner.
  • SonarQube EC2 reachable privately from Jenkins on TCP 9000.
  • Jenkins EC2 instance profile role configured for ECR push and EKS access.
  • EKS node role configured for ECR pull.
  • Jenkins credentials: sonarqube-token and postgres-db-password.

7. SonarQube EC2 setup

  1. Install and start SonarQube.
  2. Use its private DNS/IP in the Jenkinsfile's SONAR_HOST_URL.
  3. Allow TCP 9000 from Jenkins EC2 security group only.
  4. Create projects voting-app-vote and voting-app-result.
  5. Generate a token and save it in Jenkins credentials.

Worker .NET static analysis is not included in this starter pipeline.

8. IAM and EKS access

Jenkins EC2 role needs ECR authorization and push actions for the three repos, eks:DescribeCluster, and EKS access entry / policy or RBAC permissions to deploy into namespace votingapp. EKS node role needs ECR pull permissions.

aws sts get-caller-identity
aws eks describe-cluster --region ap-south-1 --name k8s-session
aws eks update-kubeconfig --region ap-south-1 --name k8s-session
kubectl get nodes
kubectl auth can-i create deployments -n votingapp
AWS authentication and Kubernetes authorization are separate. update-kubeconfig does not grant deployment permissions.

10. Manual deployment to Kubernetes

Step 1 — Connect to EKS

export AWS_REGION=ap-south-1
export EKS_CLUSTER_NAME=k8s-session
aws sts get-caller-identity
aws eks update-kubeconfig --region "$AWS_REGION" --name "$EKS_CLUSTER_NAME"
kubectl config current-context
kubectl get nodes -o wide

Step 2 — Create namespace

kubectl apply -f kubernetes/eks/00-namespace.yaml
kubectl get ns votingapp

Step 3 — Create database Secret

read -s -p "PostgreSQL password: " POSTGRES_PASSWORD
echo
kubectl create secret generic db-credentials -n votingapp \
  --from-literal=POSTGRES_USER=postgres \
  --from-literal=POSTGRES_PASSWORD="$POSTGRES_PASSWORD" \
  --dry-run=client -o yaml | kubectl apply -f -
unset POSTGRES_PASSWORD

Step 4 — Deploy data services

kubectl apply -f kubernetes/eks/01-postgres.yaml
kubectl apply -f kubernetes/eks/02-redis.yaml
kubectl rollout status deployment/postgres-deploy -n votingapp
kubectl rollout status deployment/redis-deploy -n votingapp

Step 5 — Deploy application manifests

Build/push the application images first. Jenkins updates the three application Deployments to ECR image tags after applying these files.

kubectl apply -f kubernetes/eks/03-vote.yaml
kubectl apply -f kubernetes/eks/04-result.yaml
kubectl apply -f kubernetes/eks/05-worker.yaml
kubectl get deploy,pods,svc -n votingapp
The application image fields are placeholders. The Vote/Result/Worker pods become healthy only after Jenkins updates them to real ECR images.

12. Create and run Jenkins job

  1. Push this project folder to GitHub.
  2. Create Jenkins Pipeline job votingapp-eks-cicd.
  3. Choose Pipeline script from SCM → Git and enter the project repository.
  4. Set Script Path to jenkins/Jenkinsfile.
  5. Build with parameters: app repository https://github.com/dockersamples/example-voting-app.git, branch main.
First build: Set DEPLOY_TO_EKS=false to validate Sonar, build and ECR push. After verifying ECR images and cluster access, run again with true.

15. Cleanup and cost

  • Remove only the demo namespace when finished: kubectl delete namespace votingapp.
  • ECR repositories/images remain and may incur storage charges.
  • Do not terminate the Jenkins EC2, SonarQube EC2 or EKS cluster as part of app cleanup.
  • PostgreSQL uses ephemeral storage in this sample; data can be lost on Pod replacement.
  • No public LoadBalancer or Ingress is created. Those may provision billable AWS resources.
Training-only: Harden secrets, persistent storage, TLS, RBAC, network policies, monitoring and backups before production use.
